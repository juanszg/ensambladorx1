00 / PUNTO DE PARTIDA

¿Qué es el ensamblador?

La capa legible más cercana a las instrucciones nativas del procesador.

A / DEFINICIÓN

El lenguaje ensamblador representa con mnemónicos las instrucciones que una arquitectura de CPU puede ejecutar. Un ensamblador traduce ese texto a código máquina.

ADD AX, 1 → bytes de máquina
B / IDEA CLAVE

Hay una relación estrecha entre cada instrucción y su arquitectura. Por eso, código x86 no es automáticamente código ARM: cada familia tiene su propio repertorio.

x86-64ARMRISC-V
01 / CONTEXTO

¿De dónde viene?

1940s

Los primeros programas se introducían como patrones de bits, interruptores o tarjetas perforadas.

1950s

Mnemónicos y etiquetas hicieron más legible la programación de bajo nivel. El ensamblador convertía esos nombres en códigos de operación.

HOY

Sigue presente en sistemas, firmware, compiladores, depuración y optimización especializada.

02.1 / CAJA DE HERRAMIENTAS

¿Cuáles son los ensambladores?

Traducen mnemónicos a instrucciones binarias para una arquitectura concreta.

N01

NASM

Netwide Assembler. Popular para x86 y x86-64; sintaxis Intel y directivas como section y db.

x86 · MULTIPLATAFORMA
M02

MASM

Microsoft Macro Assembler. Herramienta del ecosistema Microsoft para x86/x64 con macros y soporte de depuración.

MICROSOFT · x86/x64
T03

TASM

Turbo Assembler, de Borland. Usado en enseñanza y entornos DOS; hoy aparece sobre todo en material histórico o legado.

BORLAND · LEGADO DOS
i

Nota: el ensamblador depende de la arquitectura y su sintaxis. Elige según procesador objetivo, sistema operativo y formato de salida.

02.4 – 02.8 / ANATOMÍA DEL CÓDIGO

Una instrucción,
cuatro piezas

Una línea puede combinar etiqueta, operación, operandos y comentario. El formato varía por ensamblador.

● ● ● ejemplo.asm NASM · x86-64
01inicio:① etiqueta
02　mov rax, 42 ; carga valor② instrucción + comentario
03　add rax, 1③ mnemónico + operandos
04　ret④ instrucción sin operandos
01

Etiqueta

Nombre que señala una dirección. Sirve para saltar o referirse a una posición.

02

Mnemónico y operandos

mov nombra la operación; los operandos indican registros, memoria o valores.

03

Comentario

Texto ignorado por NASM; los comentarios comienzan con ;.

01 / DATOS

Variables y constantes

Las variables reservan espacio para valores que pueden cambiar. Las constantes nombran valores definidos para reutilizar.

section .data
contador dd 0
limite equ 10
db byte · dw palabra · dd doble · dq cuádruple
02 / CÓDIGO

Instrucciones ejecutables

Contiene operaciones y suele definir el punto de entrada esperado por el sistema o enlazador.

section .text
global _start
_start:
  mov eax, 60
En Linux x86-64, la syscall 60 termina el proceso.
03 / DIRECTIVAS

Órdenes al ensamblador

Organizan código o reservan datos durante el ensamblado; normalmente no son instrucciones de CPU.

sectionglobaldbequresb
Su sintaxis depende del ensamblador.

02.9 / PRIMER PROGRAMA

«Hola, mundo»
desde la máquina

Ejemplo NASM para Linux x86-64: write envía bytes a la salida estándar y exit termina el proceso.

01 llamada write　 02 búfer en memoria　 03 llamada exit
● ● ● hola.asm LINUX x86-64
; Escribe un mensaje y termina
section .data
mensaje db "Hola, mundo!", 10
longitud equ $ - mensaje

section .text
global _start
_start:
    mov eax, 1          ; write
    mov edi, 1          ; stdout
    mov rsi, mensaje
    mov edx, longitud
    syscall
    mov eax, 60         ; exit
    xor edi, edi       ; código 0
    syscall
▸ SALIDAHola, mundo!
